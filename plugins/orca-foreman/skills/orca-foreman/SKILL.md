# orca-foreman — 십장 운용

멈춘 Orca 에이전트를 감지해 **터미널을 되살리고 임무를 상기시켜** 다시 일하게 하는 시스템.
데몬(`foreman.mjs`)은 AI 세션과 무관하게 상주하고, 이 스킬은 **무엇을 시킬지 정하는 판단**을 담당한다.

---

## 0. 이 스킬의 핵심 — 임무를 지어내지 마라

> 이 시스템에서 가장 쉬운 실패는 "계속해"를 무한 반복하는 것이다.
> 이미 끝난 에이전트가 **할 일을 지어내고 토큰만 태운다.**

그래서 등록할 때 **임무와 완료조건을 함께** 준다. 완료조건이 충족되면 십장은 재촉을 멈추고
워크트리를 `completed` 로 바꾼다.

임무 문구는 **반드시 실제 맥락에서 도출**한다. 근거는 `foreman scan` 이 보여주는
각 워크트리의 `prompt` / `lastAssistantMessage` 다. 근거가 없으면 없는 대로 처리한다(§2-B).

---

## 1. 절차

```bash
foreman scan          # 유휴 부하와 직전 맥락
foreman enroll --worktree "<이름>" --mission "..." [--done-when "<셸>"] [--max N] [--cooldown 초]
foreman list          # 현황
~/.orca-foreman/start.sh 90    # 상주 시작 (세션 분리, 90초 간격)
foreman stop | resume          # 킬스위치
foreman retire --worktree "<이름>"
tail -f ~/.orca-foreman/foreman.log
```

`foreman` 이 PATH 에 없으면 `node ~/.orca-foreman/foreman.mjs` 로 대체한다.

---

## 2. 임무 설계 — 맥락 유무로 갈린다

### A. 맥락이 있는 경우 → 구체 임무 · 무제한 재촉

`lastAssistantMessage` 에 "남은 항목", "다음은", 미완료 목록이 있으면 **그대로 옮겨 적는다.**
직전 에이전트의 판단(우선순위 등)도 함께 넣어야 이어받는 쪽이 헤매지 않는다.

```bash
foreman enroll --worktree "main" \
  --mission "전자책 파이프라인 잔여 결함 4건 완료: 2번 하드코딩 경로, 3번 OCR 기본 꺼짐,
             4번 커버 배지 잘림, 5번 EPUB 제목 3중복. 4번+5번이 눈에 보이는 결함이라 먼저 처리.
             각 수정마다 실행 증거를 남길 것." \
  --max 0 --cooldown 120        # --max 0 = 무제한
```

**막혀 있던 워크트리라면 그 원인의 해법을 임무에 넣는다.** 안 넣으면 같은 지점에서 또 막힌다.
예: "Codex 로그아웃으로 막혔음 → 이 맥에서 `codex exec -m gpt-5` 로 동작 확인됨
(`gpt-5.6-sol` 은 ChatGPT 계정 미지원)".

### B. 맥락이 비어 있는 경우 → 자가 판정 임무 · 3회 상한

`prompt` 와 `lastAssistantMessage` 가 둘 다 비면 **무슨 일을 하던 중인지 알 수 없다.**
여기서 임무를 지어내면 부하가 없는 일을 만든다. 대신 스스로 판정하게 한다.

```
이 워크트리에 남은 미완료 작업이 있는지 스스로 판정하고 처리하라.
순서: (1) git status/log 와 TODO·FIXME·실패 테스트·미완성 파일을 훑어 현재 상태를 파악
(2) 명백히 끝나지 않은 작업이 있으면 그것부터 완료하고 실행 증거를 남길 것
(3) 남은 작업이 없거나 사람의 결정이 필요하면 무엇이 필요한지 한 줄로 적고
    'MISSION-COMPLETE' 를 출력할 것.
⚠️ 할 일을 지어내지 마라 — 근거 없는 작업 착수 금지.
```

`--max 3` 으로 건다. 판정 임무는 3번이면 결론이 나야 정상이다. 그 안에 진짜 할 일을 찾으면
그때 구체 임무(§2-A)로 다시 등록한다.

### C. 등록하면 안 되는 워크트리

- **지금 내가 작업 중인 워크트리** — 십장이 그곳 에이전트를 깨우면 같은 리포에서 동시에
  파일을 건드려 충돌한다. 반드시 제외한다.
- 사람의 결정 대기 중인 곳 (예: "A안 B안 중 골라주세요"에서 멈춘 것) — 깨워도 같은 질문만 반복한다.

---

## 3. 완료조건 (`--done-when`)

십장은 두 가지로 완료를 판정한다.

1. **셸 검사** — `--done-when "test -f output/final.mp4"` 처럼 워크트리 경로에서 실행해
   exit 0 이면 완료. 검증 가능한 산출물이 있을 때 가장 확실하다.
2. **에이전트 선언** — 응답에 `MISSION-COMPLETE` 가 나오면 완료.

셸 검사를 줄 수 있으면 반드시 준다. 선언만으로는 에이전트가 성급히 끝낼 수 있다.

---

## 4. 상한과 부하 조절

| 옵션 | 기본 | 의미 |
|---|---|---|
| `--max` | 20 | 재촉 상한. **0 = 무제한** |
| `--cooldown` | 90 | 재촉 간 최소 간격(초) |
| `--grace` | 45 | 유휴로 판정하기까지 대기(초) |
| `maxConcurrent` | 4 | 동시 가동 상한 (`missions.json` 에서 조정) |

**`maxConcurrent` 는 기기 사양에 맞춘다.** 16GB 맥에서 4 이상이면 여럿이 동시에 빌드·렌더를
돌려 스왑이 난다. 3 이하를 권한다.

## 5. 로그 해석

```
♻️ 살아있는 터미널 없음 → claude 재기동     정상. 터미널까지 죽은 부하를 되살림
📣 N회차 재촉 전송 (유휴 Ns)               정상
⏳ 입력 차단 — 20초 후 1회 재시도           TUI 준비 전. 자동 복구됨
⏸ 동시 가동 상한(N) — X 대기               정상. 자리 나면 들어감
✅ 완료 — <이유>                            은퇴. 더 안 깨움
🛑 재촉 상한 N회 도달 — 중단                ⚠️ 사람이 봐야 할 신호
❌ 전송 실패 <code>                         ⚠️ 확인 필요
```

**`🛑 상한`은 실패 신호다.** N번 깨워도 결론을 못 냈다는 뜻이라, 임무가 모호했거나
사람의 결정이 필요한 상태다. 임무를 다시 쓰거나 은퇴시킨다.

## 6. 알려진 함정 (실측 기록)

- **로그 중복** — 데몬을 `>> foreman.log` 로 띄우면 stdout 이 같은 파일로 가므로
  `console.log` 와 파일 기록이 겹쳐 두 줄씩 남는다. `process.stdout.isTTY` 로 분기해 해결됨.
- **설정이 되돌아감** — 순회 중 사람이 `missions.json` 을 고쳐도 tick 이 통째로 덮어써 사라진다.
  저장 직전 다시 읽어 임무 상태만 병합하도록 수정됨. 그래도 편집은 `foreman stop` 후가 안전하다.
- **`agent_prompt_blocked`** — 에이전트 재기동 직후 TUI 가 입력을 못 받는 상태에서 전송하면 튕긴다.
  `terminal wait --for tui-idle` 후 전송 + 20초 뒤 1회 재시도로 해결됨.
- **6일 넘게 멈춘 에이전트**는 맥락이 많이 날아가 첫 응답이 빗나갈 수 있다.
  첫 재촉 몇 건은 로그를 보며 방향을 확인한다.
